## How versions work

- Every SDK follows [Semantic Versioning](https://semver.org/) on one shared `MAJOR.MINOR` line, so
  a user who picks one minor gets the same API in every language. A new minor releases every port
  on one day; a patch is a fix in one port only. The core and the patro of one port always share a
  version and are released together.
- A data change, such as a new year's holidays, is a **patch** release of each port: no API change.
- Pre-releases need asking for by name in most package managers: an exact version in Cargo,
  SwiftPM and npm, and `--pre` with pip. npm also keeps each pre-release kind under its own tag
  (`beta`, `rc`), so `@beta` stays on the last beta after a release candidate ships.
- Python spells the version the PEP 440 way, <code>{PYPI_VERSION}</code>.

## Releases are checked

Each port's release workflow publishes from CI only, after the full test run, with build provenance
where the registry supports it: trusted publishing to crates.io, npm and PyPI, signed artifacts on
Maven Central, and attested archives for C++ and MitiBar. Each release's notes say how to check its
files.
