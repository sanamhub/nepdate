import { BENCHMARK_SPEC, OPERATIONS, benchmarks, competitorCount, formatNs, languages, nearest } from "../../../../data/benchmarks";

Every port is benchmarked on the same eight operations and the same 64 dates, defined once in the
hub's [`spec/BENCHMARK.md`](https://github.com/sanamhub/nepdate/blob/main/spec/BENCHMARK.md). Each
port, and the hub for C# NepDate, also measures every other Bikram Sambat library it could find in
its language, on the same machine and the same dates.

<p>
  None of the {competitorCount} other libraries gives the same answer as the hub's data on all 64
  dates; each report lists where they differ. In all {benchmarks.length} port languages, the port is
  faster than every other library on both conversions. In C#, OSN.NepaliCalendar is about as fast
  as NepDate, a little faster on BS to AD and slower on AD to BS, and gets 3 of the dates wrong.
</p>

## Reading the numbers

- **Compare within a row of the first table, not across languages.** Each language was measured on
  its own runtime, and Swift on GitHub's macOS runner (Apple M1), not the laptop the others used
  (Intel Core i5-12500H).
- **Some runs were not on a quiet machine.** Each report records the CPU load during its run; the
  stable release repeats them on an idle machine, pinned to one core, as the spec asks.
- **Speed is not the reason to pick a date library; correct dates are.** Every port is checked
  against the same 20,360 golden rows and 7,176 month boundaries first
  ([Same answer everywhere](/docs/project/conformance/)), and the benchmarks run only after that.
