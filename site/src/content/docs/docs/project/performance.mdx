import { BENCHMARK_SPEC, OPERATIONS, benchmarks, competitorCount, formatNs, formatRatio, languages, nearest, targets } from "../../../../data/benchmarks";

Every port is benchmarked on the same eight operations and the same 64 dates, defined once in the
hub's [`spec/BENCHMARK.md`](https://github.com/sanamhub/nepdate/blob/main/spec/BENCHMARK.md). Each
port also measures the other Bikram Sambat libraries in its language that pass the selection rule in
section 7. The C# comparison uses the same 64-date harness as the ports.

<p>
  None of the {competitorCount} other libraries gives the same answer as the hub's data on all 64
  dates; each report lists where they differ. In every language with a mature library, the port is
  faster than all of them on both conversions. Rust, C++, C and Ruby have no mature library to compare.
</p>

## Reading the numbers

- **Compare within a row of the first table, not across languages.** Each language was measured on
  its own runtime. Every row ran on the same Intel Core i5-12500H laptop, idle and pinned to one
  core as the spec asks, with one exception: Swift's only competitor ships for macOS alone, so Swift
  and that library were compared on GitHub's macOS runner (Apple M1). Swift's row in the second
  table is the laptop, in WSL 2.
- **Speed is not the reason to pick a date library; correct dates are.** Every port is checked
  against the same 20,360 golden rows and 7,176 month boundaries first
  ([Same answer everywhere](/docs/project/conformance/)), and the benchmarks run only after that.
